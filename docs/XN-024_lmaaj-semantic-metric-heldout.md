# XN-024 — LMaaJ semantic metric on held-out GEOS decks

*Generated by research-copilot*

> **⚠ STATUS — NEGATIVE / UNFAVOURABLE.** The metric was built and run as specified (90 decks,
> 3 judge families, position swapping, frozen rubric, execution calibration). It **fails** its own
> pre-registered reliability conditions and must **not** be presented as a second metric confirming
> the SIGA advantage. The thread's shippable output is a set of three *deterministic* TreeSim
> defects that need no LLM, plus a substantive negative finding about where the held-out cell
> separation actually comes from.

Full working log, every command, and the rubric-freeze timestamp:
`neurips_review/sprint/threads/B_lmaaj.md`.

## 1. Motivation

For NeurIPS 2026 submission 31642 (SIGA), three reviewers and the AC converged on one objection:
TreeSim is a structural metric and does not establish that generated GEOS input decks are
physically sensible. The specific gap targeted here: `judge_geos.NUMERIC_RTOL = 1e-6` is
effectively exact equality, so **TreeSim has no notion of how wrong a wrong value is** — a
permeability off by 2× and one off by 18 orders of magnitude score identically — and no notion of
physical equivalence (unit changes, renamed regions, equivalent formulations).

The hypothesis: an LLM judge, shown the reference deck, the candidate deck, and **the TreeSim diff
itself**, can supply the missing magnitude-and-plausibility dimension, giving a metric
interpretable as "TreeSim plus magnitude awareness."

`sha256 6b0e216eb5ff71111eafc1055c752b089b44f4330b012ea2e25070918a4dac8b`.

- **Scope.** Vanilla (`autocamp_F0`), best combo (`autocamp_F6` = S+X), and `autocamp_SE`, on

  over all 90 prompts.
- **Position swap**: order A (reference first) vs order B (candidate first), on a 30-deck seed-1
  subsample, as a control.
- **Judge families**: `openai/gpt-5.4-mini`, `google/gemini-3-flash-preview`,
  `qwen/qwen3-235b-a22b-2507`. **No DeepSeek** (the scored backbone —
  `eval_metadata.claude_model = "deepseek-v4-flash"`), no MiniMax (second scored backbone), and no
  Anthropic (vendor of the Claude Code harness). Temperature 0, via OpenRouter.
- **Four pre-registered null/unfavourable conditions**, written into the frozen rubric.

357 calls, 351 scored (98.3 %), mean per-deck mismatch coverage 0.995.

## 6. The shippable findings — three deterministic TreeSim defects

None of these needs an LLM. All were found while validating the judge's input.

### 6.1 Subtree annihilation (the sharpest)

`_bipartite_match` (`src/eval/judge_geos.py:292`) records only pairs with similarity **strictly
> 0**. For a container element with **no `name` attribute**, `compute_element_similarity` reduces
to `matched / |union \ {name}| × 0.6`. So if the reference container has zero attributes and the
candidate has even one, the score is exactly 0.0, the two are **never paired**, and the reference
element plus its **entire subtree** scores 0.

```
REF  <Solvers>                                       attrib {}
CAND <Solvers gravityVector="{ 0.0, 0.0, -9.81 }">   attrib {gravityVector: ...}
compute_element_similarity(ref, cand) = 0.0     ->  treesim_section_scores.Solvers = 0.0
```

On `ExampleProppantTest` both `<Solvers>` blocks contain **the same four solvers with the same
`name` attributes** and the same nested parameter blocks. `gravityVector = {0,0,-9.81}` is GEOS's
own default written out explicitly — and gravity is the physical mechanism the proppant-settling
task is *about*. The deck was zeroed on its entire `Solvers` section for stating the correct value
of the most physically relevant parameter in the problem.

Prevalence over all 90 held-out decks:

| Cell | decks affected | events | reference elements zeroed |
|---|---:|---:|---:|
| Vanilla (F0) | 10/30 | 23 | 167 |
| S+X (F6) | 9/30 | 19 | 137 |
| SE | 12/30 | 27 | 186 |

**31/90 (34 %) of held-out decks lose ≥1 whole subtree.** Near common-mode, so contrasts survive;
but **SE is hit hardest**, so the measured SIGA advantage is if anything understated by this defect.
It is a **cliff, not a gradient**. Artifact: `neurips_review/sprint/artifacts/B_treesim_annihilation.json`.

### 6.2 `TutorialHydraulicFractureWithAdvancedXML` scores 0.013 for every cell and seed

The reference deck is 11 687 chars raw but `load_and_resolve_dir` expands it to **351 085 chars /
3333 elements** — two orders of magnitude beyond any other reference in the set (next largest:
`TutorialDeadOilEgg`, 407). Generated decks have ~50 elements, so TreeSim ≈ 0.013 identically for
all six cells and all three seeds. An exactly-identical floor across conditions is the signature of
a metric artifact, not a modelling failure. It costs every held-out cell mean ≈ 0.099, identically.

### 6.3 TreeSim silently scores partially unparseable decks

`load_and_resolve_dir` (`judge_geos.py:125`) raises only `if parse_errors and not parsed`. A deck
where *some* files fail to parse is scored on the survivors, with no penalty and no flag:

```
F0_icl_s1 / AdvancedExampleThermoPoroElasticWellbore
  ThermoPoroElasticWellbore_smoke.xml  NOT well-formed (line 71: double hyphen in comment)
  -> load_and_resolve_dir() succeeds; eval json: status "success", treesim 0.235
```

Every instance is in Vanilla, so TreeSim **under-counts Vanilla's failures**. It becomes a hard
`xml_parse_error` only when *every* file fails (`F0_s3/ExampleProppantTest`).

### 6.4 Corrections to the description of TreeSim in the execution plan

`SIGA_rebuttal_execution_plan.md` §4.4 says TreeSim "scores tag match + `name`-attribute bonus
(0.4) + attribute-value overlap." **Two of those three constants belong to the matcher, not the
scorer.** `compute_element_similarity` (with the 0.4 name bonus and 0.6 scaling) is used **only**
to decide which elements pair; the score TreeSim reports per paired element is `attr_similarity` =
`|matching attrs| / |union of attr keys|`, with **no name bonus, no 0.6 scaling, and `name`
included in the union**. Also: matching is **greedy**, not optimal, and local to same-tag siblings
under an already-matched parent; the **root element's own attributes never enter the score**; and
each reference child contributes **1/N regardless of subtree size**. `values_equivalent`, β = 0.1,
α = 0.3, and `NUMERIC_RTOL = 1e-6` are all confirmed exactly as described. Additionally,
**nested lists fall back to case-insensitive string comparison** (`_parse_list` cannot handle
`{ {0,0,0}, {1,1,1} }`), which makes TreeSim whitespace-sensitive for `xCoords`, `Box` bounds and
similar. §4.4 must be rewritten before it is quoted.

## 7. Substantive negative finding — where the held-out separation comes from

24 of 30 (task, seed) pairs are schema-valid for **all six** cells. On those 72 decks:

| Cell | n | TreeSim | LMaaJ |
|---|---:|---:|---:|
| Vanilla (F0) | 24 | 0.8504 ± 0.1949 | 0.8851 ± 0.1352 |
| S+X (F6) | 24 | 0.8444 ± 0.1999 | 0.8823 ± 0.1511 |
| SE | 24 | 0.8462 ± 0.2011 | 0.8962 ± 0.1300 |

Every pairwise Δ is within ±0.014 with p ≥ 0.85 (Mann-Whitney U), for **both** metrics.

**On the held-out runs where every cell produced schema-valid XML, neither metric separates the
cells.** The entire measured held-out cell separation is carried by **catastrophic failures**
(3 unparseable + 3 schema-invalid decks, all Vanilla), not by graded quality on the runs that
work. This independently supports execution-plan §4.1: the **reliability** claim is the honest
headline, and the mean-lift claim on held-out is thin. Threads C/D should check this against val.

## 8. The one judge output worth shipping — the severity spectrum

| Cell | cosmetic | minor | material | severe | n differences |
|---|---:|---:|---:|---:|---:|
| Vanilla (F0) | 62.7 % | 11.0 % | 9.3 % | 17.0 % | 4169 |
| S+X (F6) | 67.0 % | 9.8 % | 9.1 % | 14.1 % | 4041 |
| SE | 65.7 % | 9.9 % | 10.1 % | 14.2 % | 3882 |

Every one of these ~12 000 differences scores **exactly zero** under TreeSim. All three judges
agree `cosmetic` is the modal class, though they disagree sharply on the share
(gemini 85 %, qwen 71 %, gpt 40 %; severe: 1.6 % / 17.0 % / 26.6 % — a 17× spread).

Defensible claim, at the strength the data supports: *the majority of attribute differences TreeSim
scores as total failures are judged physically immaterial (63-67 % per cell; individual judges
40-85 %), so TreeSim understates every cell's absolute deck quality; the effect is near
common-mode (4 pp between Vanilla and S+X), depressing levels rather than distorting contrasts.*
This is a **within-deck audit of TreeSim's absolute level**, not a between-cell measurement — the
one use that does not require the judge to be a reliable discriminator.

## 10. Caveats, stated before a reviewer states them

- This is an **LLM judging LLM output**. Reviewer nBNe asked for **simulator**-output validation;
  this is not that. It is an intermediate rung between structure and execution, and Threads
  A1/A2's execution ladder is the real answer to that ask.
- The metric's own reliability statistics are **poor** (α = 0.21; position instability equal to the
  effect size; judge choice 4.8× the effect size; one judge inverts the contrast).
- The largest LMaaJ-vs-TreeSim divergences are all one task, and they confirm the §6.2 artifact
  rather than demonstrating magnitude-blindness.
- The judge prompt was **not** tuned against results: the rubric was frozen and hashed before any
  call. One prompt-input **bug fix** was made after the mandated single-cell smoketest — the
  difference report had been asserting "no counterpart in CANDIDATE" for elements that plainly
  existed (a consequence of the §6.1 annihilation defect) — with the scoring definitions left
  byte-identical and no cross-cell comparison computed at that point. A third judge
  (`moonshotai/kimi-k2.6`) was replaced after it failed to emit the required JSON schema at all;
  its scores were never obtained. Both are logged with reasons in the thread log.

## 11. Recommendation

**Do not use the LMaaJ score table as a confirming second metric.** Ship, in descending order of
strength: §6.1 subtree annihilation, §6.2 the Advanced-XML floor, §6.3 the silent partial-parse
tolerance, §6.4 the §4.4 corrections, §7 the clean-subset null, §8 the severity spectrum (one
paragraph, judge range in the same sentence), and §5 the execution calibration with the concession
that TreeSim does it equally well.
