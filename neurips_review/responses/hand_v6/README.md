## The feedback it encodes

1. **Concision above all.** ACs are extremely busy. The same applies to reviewers, to a slightly
   reduced degree. This is in tension with demonstrating that we considered reviewer input
   carefully, and the hand version resolves that tension with bullets and short declaratives
   rather than paragraphs.
2. **Defend choices rather than concede them.** Scale is defended on cost grounds (trajectory
   runtime, number of conditions, error bars) and by establishing that contemporary works in the
   same area operate at a similar or smaller scale, with five citations.
3. **Do not itemise Reviewer kEdh's clarification requests in the AC comment.** Defer them to that
   reviewer's own thread and state only that we are happy to add clarifications.
4. **Contribution summary as a bulleted list**, leading with problem significance and framing the
   method as searching a small set of lightweight modules rather than building a new architecture.
